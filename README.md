# MAX Connect — Радар досуга

## Назначение решения
Умный координатор совместного досуга на платформе МАХ. Помогает жителям быстро находить компанию для спортивных и развлекательных мероприятий, решая проблему социального барьера.

## Основной пользовательский сценарий
1. Пользователь отправляет `/start` боту МАХ.
2. Бот присылает приветствие с кнопкой (Web App) запуска мини-приложения.
3. Открывается радар досуга (список лобби).
4. Пользователь нажимает "Присоединиться", API фиксирует отклик и отправляет уведомление в МАХ (функционал расширяется).

## Состав и архитектура решения
* Backend: Python 3.10, FastAPI (REST API + Webhook).
* Frontend: Node.js 20, React, Vite.
* Инфраструктура: Docker, Nginx.

## Запуск локальных компонентов
Команда для запуска всех локальных компонентов через Docker:
`docker compose up -d --build`

## Необходимые параметры окружения
Файл `.env.example` приложен в корне репозитория. 
Переменные окружения:
* `MAX_BOT_TOKEN` — токен чат-бота МАХ.

## Используемые порты
* `8000` — Backend API
* `5173` (внутри контейнера `80`) — Frontend Nginx

## Зависимости
* Backend: зафиксированы в `backend/requirements.txt`
* Frontend: зафиксированы в `frontend/package-lock.json`

## Внешние сервисы и интеграции
* Интеграция с Платформой МАХ (API отправки сообщений, Webhooks, Web App). Внешних БД на этапе MVP не используется.

## Описание работы с данными и порядок работы с тестовыми данными
Решение работает с синтетическими данными (п.10 Ограничений). При старте бэкенда загружается mock-список мероприятий. Для воспроизводимой проверки работы API в репозитории приложен файл `test_data.json` с эталонной структурой.

## Пошаговый сценарий проверки
1. Открыть бота МАХ по юзернейму (указан в презентации).
2. Отправить команду `/start`.
3. Нажать кнопку "Открыть Радар Уфы".
4. Убедиться в загрузке списка мероприятий.

## Примеры ожидаемого поведения системы
* GET `/api/lobbies` возвращает статус 200 и JSON массив объектов из `test_data.json`.
* POST `/api/webhook` при получении `/start` возвращает 200 OK и инициирует асинхронную отправку сообщения через API МАХ.

## Известные ограничения
В MVP не реализована постоянная база данных (PostgreSQL), данные хранятся в памяти приложения для упрощения развертывания.

## Порядок остановки и повторного запуска решения
Остановка: `docker compose down`
Повторный запуск: `docker compose up -d`

## Работа с данными
В соответствии с п. 10 ограничений регламента, в текущей версии MVP вместо реального подключения к внешней информационной системе используются заранее подготовленные смоделированные мок-данные для пилотного региона (г. Уфа). 
Порядок работы с тестовыми данными: эталонный массив сборов доступен в файле `test_data.json`. При инициализации базы данных бэкенд автоматически загружает эти данные в In-Memory хранилище SQLite.
